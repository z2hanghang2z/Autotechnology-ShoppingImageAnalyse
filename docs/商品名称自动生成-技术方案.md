# 手机壳商品名称自动生成 · 技术方案

> **当前范围：只做「商品名称生成」这一件事，其他功能暂不实现，但架构上已预留扩展位。**
>
> 输入：一份待上架商品 Excel ｜ 输出：同一份 Excel，商品名称已填好

---

## 一、项目目标

把「人工给每个手机壳写商品名称」这件事自动化。

运营只需要准备好一份 Excel（商品资料 + 主图），跑一条命令，
视觉模型读图生成特征词，程序按规则组装出合规的商品名称，写回表格。

## 四、商品名称生成规则

### 4.1 长度（硬性）

- **写满 100 字符，不能多不能少**
- **计数口径：1 个汉字 = 2 字符，1 个英文/数字/符号 = 1 字符**
- **名称中绝不能有空格**（用户 2026-09-22 明确），必须用中文或英文填满
- 即 100 字符 ≈ 50 个汉字
- 配置位置：`config/title_rules.yaml` → `length.target` / `length.count_mode`

> **为什么不靠模型数长度？** 模型数不准。实测让它写 100 字，会写成 87 或 112。
> 所以改成「模型只出关键词池 → 程序确定性组装 → 精确凑满」。
> 凑满用「贪心选取 + 子集和补位」，**绝不切断词语**。

**★ 奇偶约束与「换词翻转」机制**

汉字算 2、英文算 1 → 总长度存在**奇偶约束**。缺口为奇数（尤其差 1 字符）时，
补足词池里**没有任何词能填**（最短的词也有 3 字符）。

早期实现是往末尾塞一个**空格**兜底，但用户明确禁止名称含空格。现改为**换词翻转奇偶**：

| 手段 | 位置 | 做法 |
|---|---|---|
| A. 奇数词前置 | `_fill` | 缺口为奇数时，把奇数长度的词提到词池最前，让贪心一定取到 |
| B. 放弃一词重建 | `_fill` | 逐个放弃一个已用关键词后重建，总长度奇偶随之翻转 |
| C. 被拦词下轮再试 | `_build` | 因英文粘连被跳过的词留到下一槽位再试，**不再直接丢弃** |

> **手段 C 是根因修复**：`ins风`/`Q版`/`3D立体` 这类奇数长度的词**都以英文开头**，
> 排在机型段（结尾是数字，如 `适用于苹果18`）后面会被 `can_join()` 防粘连拦掉。
> 旧实现「拦掉即丢弃」，导致奇数词永远用不上 → 缺口永远是奇数 → 只能塞空格。

配置 `parity_filler` 已改为空字符串。极少数仍凑不满时，报
「无法精确凑满目标长度」交由重试机制处理 —— **宁可报错也不塞空格**。

实测：6 类机型组合 × 5 模板 × 3 轮换 = **90/90 全部精确 100 字符且无空格**。

### 4.2 必填词

必须同时包含（配置：`config/required_words.yaml`）：

| 类别 | 词 |
|---|---|
| 核心词 | 手机壳 |
| 品牌词 | 苹果、iPhone |
| 属性词 | 新款、防摔 |
| 材质词 | 材质库中命中至少一个（液态素皮/软硅胶/磨砂/透明…） |

机型规范化后必须带「苹果」前缀，如 `适用苹果iPhone18U`。

### 4.3 机型规则（多机型 + 多品牌）

**基本规则**
- 机型来源是表格的**独立机型列**（默认 D 列），不再从第一列解析
- 机型关键词全标题只出现一次
- 模型被明确禁止输出任何机型信息（由商品资料提供）
- **解析不出机型时该行直接跳过报错，绝不编造机型 / 品牌**

**★ 品牌按实际机型自动切换**

本类目不只卖苹果壳，机型列会出现华为等其它品牌。品牌必须按**实际内容**判定：

| 品牌 | 只有 1 个机型 | 第 1 个机型（多机型） | 第 2 个机型 | 第 3 个起 |
|---|---|---|---|---|
| 苹果 | `适用于苹果iPhoneDuo` | `适用于苹果18` | `iPhone17` | `16`（裸写） |
| 华为 | `适用华为PuraXMax` | `适用华为PuraXMax` | 裸写 | 裸写 |

品牌表在 `config/required_words.yaml` → `brands`，
含 `aliases` / 四个 `title_template*` / `brand_words` / `require_brand_words`。

**★ 品牌词必须出现**（`require_brand_words: true`，校验会拦）

苹果商品要求「苹果」「iPhone」**都出现**：
- **多机型**时分别由第 1、第 2 个机型承载（`适用于苹果18` + `iPhone17`）
- **单机型**时没有第 2 个机型可承载 `iPhone`，必须靠
  `title_template_single`（`适用于苹果iPhone{model}`）**一次带齐**

> **踩坑记录**：早期重构时把机型文本的品牌前缀统一剥掉，
> 单机型 `iPhoneDuo` 就变成了 `适用于苹果Duo`——**「iPhone」丢了**。
> 现在单机型走 `title_template_single`，且校验强制品牌词必须出现。

> **踩坑记录（2026-09-22）**：旧实现把品牌写死成「适用于苹果」，且
> `must_include` 里硬性要求「苹果」「iPhone」。当机型列出现华为机型时，
> 解析器识别不了华为机型 → 回落到写死的 `tpl.format(model="iPhone")`
> → 标题变成「适用于苹果iPhone…」——**虚假品牌宣称**，会导致退货。
>
> 三处修复：① 品牌表 + 按品牌选模板；② 解析失败改为报错跳过；
> ③ 校验新增「不得出现非本商品品牌词」的反向拦截。
> 同时把「苹果」「iPhone」从 `must_include` 移除——品牌词由品牌表承载。

**多机型支持**

一个手机壳常适配多个机型，机型列里出现的疑似机型**全部算适配机型，都要进名称**。

| 机型列写法 | 解析结果 | 标题中 |
|---|---|---|
| `iphone18/17/16/15/14` | iPhone18、17、16、15、14 | 适用于苹果**18** … iPhone**17** … **16** … **15** … **14** |
| `透明、iPhone18Pro/17ProMax/16/18pm` | 18Pro、17ProMax、16、18ProMax | 适用于苹果**18Pro** … iPhone**17ProMax** … **16** … **18ProMax** |
| `硅胶、iPhone18ProMax/苹果17Pro/17pm/18p` | 18ProMax、17Pro、17ProMax、18Pro | 适用于苹果**18ProMax** … iPhone**17Pro** … **17ProMax** … **18Pro** |
| `素皮、华为puraXMax/华为puraXMax典藏版` | **2 个**：华为PuraXMax、华为PuraXMax典藏版 | 适用华为**PuraXMax** … **PuraXMax典藏版** |
| `iPhone Duo` | iPhoneDuo | 适用于苹果**iPhoneDuo** |

> **「典藏版 / 限量版」算独立机型**，**不能**当尾部修饰词剥掉。
> 即 `华为puraXMax/华为puraXMax典藏版` 是 **2 个机型**，两个都要进标题。
> （`_MODEL_TAIL_WORDS` 里刻意不含这几个词。）

**★ 机型穿插而非连写**

机型**与属性词交替出现**，不是连成一串：

```
适用于苹果18玛丽猫手机壳iPhone17迪士尼16透明15新款超轻薄14防摔散热支架软壳…
        ↑第1个机型          ↑第2个           ↑第3    ↑第4    ↑第5
```

实测依据：2456 条真实标题中 **63% 列了 5 个以上机型**（7 个机型占 31%）。

**机型列里的杂质会被剥掉**
- 材质前缀：`素皮、iPhoneDuo` → `iPhoneDuo`（`strip_material_prefix`）
- 尾部修饰词：`华为puraXMax典藏版` → `PuraXMax`（`_MODEL_TAIL_WORDS`）
- 后缀别名：`18pm` → `18ProMax`、`17p` → `17Pro`（`model_suffix_aliases`）

**★ 槽位容量兜底**：模板里 `model_n` 的数量决定了能放几个机型。
机型多于槽位时，`_resolve_pattern` 会**自动补足槽位**，
且每个补位机型前面插一个关键词槽，保证机型之间不相邻。

**路径 vs 机型列表的歧义处理**

斜杠既可能是路径分隔符，也可能是机型分隔符。判据：
**若按斜杠切开后每一段都能解析出机型，则认为是机型列表，不是路径。**

```python
'苹果18u/17promax/16'  -> 机型列表 ['iPhone18U','iPhone17ProMax','iPhone16']  ✓
'/usr/local/images'    -> 路径（各段无机型特征）
```

**规则：不质疑机型列文本中信息的真实性**——只要出现疑似机型就当适配机型处理。

### 4.4 ★ 标点符号禁止

**商品名称中不允许出现任何标点符号**（含 `/`、空格等分隔符）。

实现：
- `title_builder.PUNCT_RE` 定义禁止字符集（中英文标点全覆盖）
- `validate_title` 的 `check_punctuation` 开关（默认开）
- 模型关键词里含标点的**直接丢弃**（`filter_keywords`）

**连带影响：不能靠分隔符解决「英文粘连」**

模板把特征词前置时，会出现「适用苹果iPhone17Pro + ins风」这种粘连
（`Pro` 与 `ins` 贴在一起，搜索引擎会切错词）。

原方案是插空格分隔，但**空格同样属于分隔符**，会带来两个问题：
1. 违反「不能有标点」的要求
2. 若平台导入时过滤空格，长度会从 100 变成 99

**现方案**：组装时**跳过**会造成粘连的关键词（`can_join()` 判断），
改用下一个词或补足词来填，全程不加任何分隔符。

### 4.5 ★ 固定段长度预留（重要机制）

组装模板允许把机型段/核心词段/材质放到**任意位置**。
但固定段承载全部必填词，**必须保证它们一定放得下**。

**做法**：先算出所有固定段的总长度，加关键词时预留这部分余量：

```python
if W(cand) + remaining_text_weight <= target:
    加入该关键词
```

**踩过的坑**：早期实现没预留，当模板把机型段放到后面时，
前面的关键词会吃光长度预算，导致机型段被截断成
「适用苹果iPhone18U17Pr」这种半截文本——必填词直接废掉。

### 4.6 差异化（避免标题雷同）

四道措施（配置：`config/title_rules.yaml` → `differentiation` + `structure`）：

1. **组装模板按行轮换** —— 6 个模板轮着用，标题前半段不雷同
2. **补足词跨商品不重复** —— 本批用过的词，后续商品优先不用
3. **关键词顺序按行轮换**
4. **生成后输出相似度报告** —— 超 0.85 告警、超 0.95 判定不合格

**组装模板**（可自由增删改，不用动代码）：

| # | 模板 | 效果 |
|---|---|---|
| 1 | `[keywords_a, model_prefix, core_suffix, keywords_b, material, padding]` | 特征前置 |
| 2 | `[model_prefix, core_suffix, material, keywords, padding]` | 经典式 |
| 3 | `[model_prefix, keywords_a, core_suffix, keywords_b, material, padding]` | 特征夹心 |
| 4 | `[core_suffix, model_prefix, keywords_a, material, keywords_b, padding]` | 核心词前置 |
| 5 | `[model_prefix, material, keywords_a, core_suffix, keywords_b, padding]` | 材质提前 |
| 6 | `[keywords_a, core_suffix, model_prefix, keywords_b, material, padding]` | 特征前置+核心词居中 |

> 固定段（机型段/核心词段/材质）承载全部必填词，**无论模板怎么排都不会丢**。

### 4.7 违禁词

配置：`config/forbidden_words.yaml`，按类别维护：

| 类别 | 举例 |
|---|---|
| 绝对化用语 | 最好、第一、顶级、唯一、100% |
| 授权类宣称 | 授权、正版、官方授权、独家授权 |
| 虚假宣传 | 永久、万能、一劳永逸 |
| 医疗功效 | 治疗、杀菌、抗菌 |
| 品牌侵权 | 原装正品、官方正品 |
| 敏感规避 | 高仿、复刻、免税 |
| 水印标识 | wf、wj、店铺 |
| 跑题类目 | 钢化膜、充电器、数据线 |

**实测教训**：模型曾自行写出「迪士尼授权正版」——品牌授权宣称无证明即违规，已加入词库。

### 4.8 其他禁止项

- 禁止模型自创英文品牌名（实测编出 `timeLUCKYEH`）→ `ascii_filter` 拦截
- 禁止水印文字混入标题
- 禁止机型推断（模型绝不允许自行判断适配机型）

### 4.9 ★ 条件必含词（按特征强制插入）

有些特征一旦具备就**必须写进标题**，且**不能被长度控制挤掉**（作为固定段插入）。

| 特征 | 必含词 | 判定来源 |
|---|---|---|
| 迪士尼联名 | `迪士尼联名` | A 列含 `迪士尼` 或 `IP联名` |
| 磁吸 | `磁吸magsafe` | 资料或模型关键词含磁吸类词 |
| 支架 | `支架` | 资料含「支点」等，或模型关键词含支架类词 |
| 挂绳 | `带挂绳` | 资料或模型关键词含挂绳类词 |

配置：`required_words.yaml` → `conditional_words`
判定：`detect_features(row_data, model_keywords, required_cfg)`，两个来源任一命中即算具备

**★ 迪士尼联名的风险边界（重要）**

`IP联名` 是路径里的**分类目录名**（`02-IP联名`），它本身**不等于**迪士尼。
当前该目录下全部是迪士尼联名，故以其为触发条件。

> ⚠️ 若该目录出现**非迪士尼 IP**（三丽鸥、宝可梦、名侦探柯南…），
> 标题会被错扣「迪士尼联名」→ **虚假品牌宣称，有法律风险**。
> 届时必须把 `IP联名` 从 `detect_in_data` 删掉，只保留「迪士尼」。

**通用原则**：凡「产品属性宣称」类词（支架 / 挂绳 / 磁吸 / 防水 / 联名），
**必须走条件判定**，绝不能放无条件词库 —— 产品没这功能就是虚假宣传。

> 对**法律风险类**特征，图片判断（`detect_in_keywords`）应保守：
> 迪士尼联名故意留空该字段，宁可漏加（少个卖点）不可错加（虚假宣称）。

## 五、核心架构决策

### 5.1 模型只做「感知」，不做「硬参数」

| 谁负责 | 内容 |
|---|---|
| **视觉模型** | 颜色、图案、风格、图上文字 → 特征关键词池 |
| **商品资料（第一列）** | 材质、系列、适配机型 |
| **程序** | 长度控制、必填词、违禁词、差异化 |

**理由**：彻底规避「AI 编造参数」。适配机型写错会直接导致买家退货，
材质写错属于虚假宣传——这类硬参数绝不能交给模型猜。

### 5.2 配置与代码分离

```
config/
├── model_config.yaml     模型名 / 地址 / 温度 / 并发 / think 开关 / 重试
├── title_rules.yaml      长度口径 / 组装模板 / 差异化 / 校验开关
├── required_words.yaml   必填词 / 材质库 / 补足词池 / 英文白名单
└── forbidden_words.yaml  违禁词库（分类维护）
```

**换品类、换平台、换模型，只改配置，代码一行不动。**

### 5.3 思考模式必须关闭

`qwen3.5:9b` 是思考型模型，默认会输出一大段推理再给答案，**慢 7.9 倍**。

| 模式 | 耗时 | 输出 tokens |
|---|---|---|
| `think: true`（默认） | 8.67 秒 | 504 |
| **`think: false`** | **1.10 秒** | **60** |

配置：`config/model_config.yaml` → `inference.think: false`

> 注意：关闭 thinking 主要改善「单张响应速度」，对「批量吞吐」帮助有限
> （瓶颈在 GPU 算力上限，不在输出长度）。

### 5.4 温度设为 0.0

实测 `temperature=0.1` 时同一张图多次调用结果不同，破坏流水线幂等性。
`temperature=0.0` 时 4/4 完全一致。

## 六、⚠️ 技术红线（踩过的坑，绝不能重犯）

### 6.1 Excel 写入

| 红线 | 原因 |
|---|---|
| **绝不能用 openpyxl 保存带图片的 Excel** | 会丢弃 `xl/media/*`、`xl/richData/*`、`xl/metadata.xml`、`xl/printerSettings/*` |
| **绝不能用 ElementTree 整体解析重写 XML** | ET 会吞掉 xmlns 声明并改写命名空间前缀，导致 `mc:Ignorable="x14ac xr xr2 xr3"` 引用的前缀未声明 → Excel 报 XML 错误、进入修复模式 |
| **必须用字符串级定点替换** | 只改目标单元格那一小段，其余字节原样搬运 |
| **写后必须验证三项** | XML 良构性 + 图片 md5 + 逐字节差异范围 |
| **写前必须备份** | 脚本自动生成带时间戳的 `*_backup_YYYYMMDD_HHMMSS.xlsx` |

### 6.2 Excel 读取

| 红线 | 原因 |
|---|---|
| **单元格内图片 openpyxl 读不到** | 单元格值显示 `#VALUE!`，`ws._images` 为空；必须走 zip + XML 解析 |
| **图片位置不固定** | 实测同一份文件在不同工具保存后，图片可能在 `xl/media/`，也可能在 `xl/richData/media/`；**必须按 rels 相对路径解析，不能写死路径** |
| **命名空间不标准** | `richValueRel.xml` 用 `.../spreadsheetml/2022/richvaluerel`，且可能带前缀（`xlrvrel:rel`）→ 必须用忽略命名空间的标签名匹配 |
| **共享字符串要解析** | 否则 `t="s"` 的单元格只能读到索引数字 |

### 6.3 模型调用

| 红线 | 原因 |
|---|---|
| **必须传 `think: false`** | 否则慢 7.9 倍 |
| **必须设 `num_predict` 上限** | 实测出现过单次 3881 tokens / 耗时 69 秒的失控 |
| **必须有网络重试** | Ollama 服务可能中途崩溃（502 Bad Gateway / RemoteDisconnected） |
| **调用前做健康检查** | `ollama_client.health_check()` |

### 7.1 为什么提供 `run.bat`

用户环境是 Windows PowerShell。直接在 PowerShell 里调用带引号的解释器路径
必须加调用运算符 `&`，否则报「表达式或语句中包含意外的标记」：

```powershell
& "C:\...\python.exe" scripts\run.py --check     # ✅ 正确
"C:\...\python.exe" scripts\run.py --check       # ❌ 报错
```

批处理封装把这个坑藏起来，使用者只需：

```powershell
.\run.bat --check
.\run.bat "referexcel\上架安排.xlsx" --dry-run
```

### 7.2 ⚠️ 批处理文件的两条硬性约束（改 `run.bat` 时务必遵守）

`.bat` 是 Windows 上最容易出编码问题的文件类型。实测踩过坑，
**以下两条必须同时满足，否则 cmd.exe 会逐行错乱解析**：

| 约束 | 说明 | 违反后的症状 |
|---|---|---|
| **必须是 CRLF 行尾** | `.bat` 不支持 LF 行尾 | 报 `'n.bat' 不是内部或外部命令` 之类的碎片错误 |
| **内容必须是纯 ASCII** | cmd.exe 用系统 ANSI 码页（中文系统是 GBK）读 `.bat`，不是 UTF-8 | 中文变乱码（`璇风‘璁?`），乱码还会破坏语法解析 |

**因此 `run.bat` 里的提示信息一律用英文**，中文输出交给 Python 负责。

**中文输出怎么保证不乱码**：批处理里设置

```bat
chcp 65001 >nul
set PYTHONUTF8=1
set PYTHONIOENCODING=utf-8
```

让 Python 用 UTF-8 输出，控制台也切到 UTF-8 码页。
（`run.py` 会打印 `═`、`✅`、`⚠` 等符号，这些在 GBK 码页下会直接抛
`UnicodeEncodeError`，所以必须走 UTF-8。）

**修改 `run.bat` 的正确姿势**：用支持指定编码的编辑器另存为
「ANSI 编码 + CRLF 行尾」，或直接用脚本生成（内容 ASCII + `\r\n` 拼接）。

## 十、故障处理

| 现象 | 处理 |
|---|---|
| `Ollama 服务不可用` | 启动 `ollama.exe serve`（需带 `OLLAMA_MODELS` 环境变量） |
| `502 Bad Gateway` / 连接中断 | 脚本已内置指数退避重试；若持续失败说明服务崩了，重启即可 |
| `未在单元格中发现图片` | 确认图片是「放置在单元格中」的内嵌图，不是 `=IMAGE()` 链接公式 |
| `单元格关联着内嵌图片，拒绝覆盖` | 目标列与图片列冲突，用 `--name-col` 指定别的列 |
| Excel 提示需要修复 | 立即用 `*_backup_*.xlsx` 恢复，并检查写入模块是否被改动 |
| 生成结果不理想 | 改 `config/required_words.yaml`（补足词池）或 `title_rules.yaml`（模板），不用改代码 |
