### 二选一必填词 `must_include_any`（1 组）

**组内任选一个**出现即可，按行轮换（第 1 行用第 1 个、第 2 行第 2 个……循环）。

| 组 | 候选 | 长度 |
| --- | --- | --: |
| 新款组 | `新款` | 4 |
| | `2026新款` | 8 |

> 目的：同一批商品不会千篇一律都用「新款」，增加名称多样性。  
> **用轮换而非真随机**，是为了可复现 —— 同一批数据跑两次结果一致。

## 五、机型附加词 `model_extra_words`（1 条规则）

机型名里出现 `match` 片段时，标题中**额外**加入 `add` 里的词（穿插在属性词之间）。

| match | add | 说明 |
| --- | --- | --- |
| `Duo` | `duo` `DUO` | 机型 iPhoneDuo → 除「Duo」外还要各出现一次 `duo`、`DUO` |

> **实现要点**：这些词通过 `assemble_exact(priority_keywords=...)` 传入，
> **不参与轮换、固定优先取用**。  
> 踩过的坑：曾把它们放进普通词池，结果被 `rotate` 轮换挤到队尾，
> 关键词槽位在前面就填满了，永远取不到。

## 六、补足词池 `padding_pool`（28）

最后兜底用，按顺序取。**★ 标记的是含英文字符的奇数长度词。**

```
全包镜头  保护套  超薄  高级感  男女款  情侣款  简约  时尚
个性      创意    网红  潮流  ★ins风  小众  日系  韩系
可爱      卡通  ★Q版  磨砂质感  防刮花  抗震  防滑  散热
轻薄      亲肤  IP  现货
```

**★ 奇数长度词（2 个）**

| 词 | 长度 |
| --- | --: |
| ins风 | 5 |
| Q版 | 3 |

> ⚠️ **这 2 个词是「名称禁止空格」能成立的命脉。**  
> 汉字算 2、英文算 1，奇数缺口只能靠奇数长度的词补。  
> 而它们**全部以英文开头**，删掉任何一个都可能让长度凑不满 100。  
> 建议：给运营词库也补几个含英文的奇数长度词，把能力分散开。

> **如何自己判断一个词是不是奇数长度**：  
> 汉字 = 2、ASCII = 1 → **奇数长度 ⟺ ASCII 字符个数是奇数**。  
> 即「1 个字母 + 汉字」（`Q萌`=3）、「3 个字母 + 汉字」（`ins风`=5）、或「纯 3 字母」（`TPU`=3）。

```

```

**★ 每类词限量**（`word_banks.max_per_title`）

```yaml

  precise_words: 1     # 精准词是长尾词，堆多了挤占搜索词/卖点词
```

被限量的类别会**按行轮换**取词，保证跨商品不总是同一个。

> ⚠️ **限量要在所有取词通道上生效**：`padding_pool` 里也有「男女款/情侣款」，
> 补长度时会**绕过限量**又塞一个进来。实现上要把「被限量类别里的词」从补足词池剔除。

键位保留为空列表，仅为兼容旧配置。

## 八、条件必含词 `conditional_words`（4）

命中即作为**固定段**插入，**不会被长度控制挤掉**。

| 特征 | 取词方式 | 从 A 列判定 `detect_in_data` | 从图片判定 `detect_in_keywords` |
| --- | --- | --- | --- |
| 迪士尼联名 | 固定 `迪士尼联名` | 迪士尼 / Disney / disney / DISNEY / IP联名 / ip联名 / Ip联名 | **（留空）** |
| 磁吸 | 固定 `磁吸magsafe` | 磁吸 / magsafe / Magsafe / 磁力 / 磁吸壳 / 磁吸款 | 磁吸 / 磁力 / 无线充 / magsafe / Magsafe / 磁吸环 |
| **支架** | **轮换 4 选 1** | 支架 / 支点 / 立式 / 可立 | **（已清空）** |
| 挂绳 | 固定 `带挂绳` | 挂绳 / 挂链 / 吊绳 / 手绳 | **（已清空）** |
| **折叠屏** | **轮换 3 选 1** | **折叠** | **（已清空）** |

### ★ 支架：4 个词按行轮换

```
支架  →  支点  →  旋转支架  →  360旋转支架  →  支架  → …
```

| 词 | 长度 |
| --- | --: |
| 支架 | 4 |
| 支点 | 4 |
| 旋转支架 | 8 |
| 360旋转支架 | 11 |

### ★ 折叠屏：3 个词按行轮换（2026-09-22 新增）

```
折叠屏  →  阔折叠  →  阔折叠屏  →  折叠屏  → …
```

触发依据：路径里的分类目录名，如 `Z:\1-产品图片\2-折叠\...`

### ⚠️⚠️ 为什么「支架 / 挂绳」清空了图片判定

实测模型会把「支架」「挂绳」当成**通用功能词**输出（提示词让它覆盖"功能"维度），
图片里根本没有对应结构，条件词却被触发 → **无支架商品被写「支架」= 虚假宣传**。

```
第1行 模型关键词 ['磁吸','中轴','全包',...,'支架',...]   ← 商品没有支架
第5行 模型关键词 ['米妮','可爱',...,'挂绳',...]         ← 商品没有挂绳
```

**区分标准**：

| 类别 | 例子 | 放哪 |
| --- | --- | --- |
| **通用保护性宣称** | 防摔 / 防刮 / 全包 / 散热 / 防指纹 | 可放无条件词库（行业通用） |
| **结构性功能** | 支架 / 挂绳 / 磁吸 / 防水 / 联名 | **必须走条件判定，且只从 A 列** |

> 同理 `旋转支架` 曾被误搬进 `selling_words`（无条件词库）→ 无支架商品也被写。
> **结构性功能词绝不能放无条件词库。**

> ⚠️ **待处理**：`磁吸` 目前仍保留图片判定，同一风险未处理。

> **迪士尼联名的 `detect_in_keywords` 故意留空** —— 图片有卡通图案就判迪士尼误判率太高。  
> 法律风险类特征：**宁可漏加（少卖点），不可错加（虚假宣称）**。
>
> ⚠️ `IP联名` 是路径里的**分类目录名**，不等于迪士尼。  
> 若该目录以后放进非迪士尼 IP（三丽鸥 / 宝可梦 / 柯南），必须把它删掉、只留「迪士尼」。

#### 1. 奇数长度的词只剩 2 个，且全在补足词池


**这是「名称禁止空格」能成立的唯一命脉。** 删掉这 2 个词中任何一个，

#### 3. 源数据重复会导致标题相似

原因是这两行的 **A 列和 D 列完全相同** —— 是同一商品重复录入。

## 十二、核心元素（设计 / 图案）

**要求**：每条标题至少出现 1 个**设计/图案元素**（如「城堡」「大象」「彩虹」「米妮头像」）。

**为什么需要**：`structure.model_keyword_quota: 15`（模型词占比 ≤15%）只保留模型关键词
**最前面 3~4 个**，而设计元素排在列表后面 → **每次都被截掉**，
标题里全是「可爱 / 简约 / 高级感」这类通用词，看不出商品长什么样。

**来源**：模型 `observed.图案` 字段，例：

```
第1行  observed.图案 = "城堡、英文字母"          → 核心元素 ['城堡']
第4行  observed.图案 = "米妮头像、甜甜圈、彩色糖屑" → ['米妮头像','甜甜圈','彩色糖屑']
第7行  observed.图案 = "大象、彩虹、花朵、蛋糕…"   → ['大象','彩虹','花朵','蛋糕',…]
```

**配置**（`required_words.yaml` → `core_elements`）

```yaml
core_elements:
  enabled: true
  max_per_title: 2     # 每条最多几个核心元素放最优先位置（至少保证 1 个）
  exclude: [英文字母, 字母, 文字, 图案, 纯色, 无, 其他, 不规则, 元素, 背景]
```

> ⚠️ `max_per_title` 调大能覆盖更多设计元素，但**源数据重复的行相似度会升高**
> （实测 3 个时行 4↔行 5 达 0.871，超 0.85 告警线；降到 2 后消失）。
>
> 实现上通过 `assemble_exact(priority_keywords=...)` 传入，**不参与轮换** ——
> 否则会被 `rotate` 转到队尾取不到。
