### 第 1 步：准备表格

新建或打开你的待上架商品 Excel，按下表格式填好：

| 列       | 内容                   | 示例                     |
| ------- | -------------------- | ---------------------- |

>   
> 如果图片能随意拖动、单元格里是空的，那是浮动图片——**浮动图片也支持**，
>   
> 但推荐用「放置在单元格中」更整齐。

把表格放到项目的 `referexcel\` 目录下（位置要求见 3.5 节）。

先看看效果满不满意，不满意就改配置（见第五节）再来。

## 三、表格格式要求

> 一张表需要 4 列：**商品资料（A）｜商品主图（B）｜商品名称（C，留空）｜适配机型（D）**

### 3.1 第一列（A 列）：商品资料

程序会从中提取两类信息（**机型不再从这里取**，见 3.4）：

| 信息 | 提取方式 |
|---|---|
| **材质** | 在文本里匹配材质库（`液态素皮`/`软硅胶`/`磨砂`/`透明`…）；匹配不到才让模型看图判断 |
| **系列** | 找带「系列」字样的段 |

**支持两种格式：**

**格式 A：文件路径**（当前在用）
```
Z:\1-产品图片\2-折叠\F1-清雅系列-壳膜一体\02-IP联名\250430-粉红玛丽\粉红玛丽\苹果Duo
```
→ 系列=清雅系列 | 材质=（路径里没有则让模型看图判断）

**格式 B：结构化文本**（推荐，解析最准）
```
液态素皮 云花系列
```
→ 系列=云花系列 | 材质=液态素皮

### 3.2 第二列（B 列）：商品主图

- 每行一张主图
- 支持「放置在单元格中」的内嵌图片，也支持浮动图片
- 支持格式：png / jpg / jpeg / webp / bmp

### 3.3 第三列（C 列）：商品名称（生成结果）

- 默认写在**图片右侧的那一列**
- 如果表里已有「商品名称」表头，会写进那一列
- 想写到别处：加 `--name-col` 参数


### 3.4 第四列（D 列）：适配机型 ← **重点**

**机型单独放在 D 列**，一个格子可以写多个机型。

**写法**：第一个写完整的品牌（`iphone` / `华为`），后面的用 `/` 分隔

| D 列写法 | 解析结果 | 标题里的呈现 |
|---|---|---|
| `iphone18/17/16/15/14` | 5 个机型 | 适用于苹果**18** … iPhone**17** … **16** … **15** … **14** |
| `iphone18/17/16ProMax` | 3 个机型 | 适用于苹果**18** … iPhone**17** … **16ProMax** |
| `iphoneDuo` | 1 个机型 | 适用于苹果**iPhoneDuo**（单机型，苹果 + iPhone 都出现） |
| `苹果17pro支点` | 1 个机型 | 适用于苹果**iPhone17Pro** |
| `华为puraXMax/华为puraXMax典藏版` | **2 个机型** | 适用华为**PuraXMax** … **PuraXMax典藏版** |
| `透明、iPhone18Pro/17ProMax/16/18pm` | 4 个机型 | 适用于苹果**18Pro** … iPhone**17ProMax** … **16** … **18ProMax** |

> **「典藏版」「限量版」算独立机型**，不会被当成修饰词丢掉。
> 即 `华为puraXMax/华为puraXMax典藏版` 是 **2 个机型**，两个都会进标题。

**★ 品牌会自动识别**（2026-09-22 新增）

程序从 D 列文本里判断品牌，再决定标题怎么写：

| 品牌 | 只有 1 个机型 | 第 1 个机型（多机型） | 第 2 个机型 | 第 3 个起 |
|---|---|---|---|---|
| 苹果 | 适用于苹果**iPhone**Duo | 适用于苹果**18** | iPhone**17** | **16**（裸写） |
| 华为 | 适用华为**PuraXMax** | 适用华为**PuraXMax** | **…**（裸写） | 裸写 |

- 写 `华为puraXMax` 就生成「适用华为PuraXMax」，**绝不会**出现苹果字样
- **苹果商品要求「苹果」「iPhone」都出现**：多机型时分别由第 1、第 2 个机型承载；
  单机型时由 `title_template_single`（`适用于苹果iPhone{model}`）一次带齐
- 品牌表在 `config/required_words.yaml` → `brands`，加品牌照格式加一条即可
- 没写品牌时按 `default_brand`（默认苹果）处理，兼容 `18U` 这类裸机型写法

> ⚠️ **为什么必须按品牌判定**：曾经这里是写死的「适用于苹果」，导致华为商品的
> 标题里冒出「适用于苹果iPhone」——这是**虚假品牌宣称**，会被投诉甚至退货。
> 现在除了按品牌切换，校验还会拦截「华为商品里出现苹果品牌词」的情况。

**标题里怎么排布**（对齐真实生产标题的写法）：

```
适用于苹果18玛丽猫手机壳iPhone17迪士尼16透明15新款超轻薄14防摔散热支架软壳…
        ↑第1个机型          ↑第2个           ↑第3    ↑第4    ↑第5
```

- **第 1 个机型**带品牌前缀
- **第 2 个机型**带「iPhone」前缀（仅苹果；其它品牌裸写）
- **第 3 个起**裸写，**穿插在属性词之间** —— 既覆盖全机型搜索词，又不显得堆砌
- 每个机型都会出现在标题里，程序会自动校验

> **为什么要穿插**：实测你的 2456 条真实标题里，**63% 列了 5 个以上机型**，
> 其中 7 个机型的占 31%。机型穿插是你们的核心打法，现在程序已对齐。

**D 列可以混写材质**：程序会自动剥掉 `素皮、` `透明、` 这类材质前缀，
只把机型部分拿去解析。但**建议还是尽量只写机型**，最稳妥。

**⚠️ 机型写不出来会怎样**：该行 **C 列不会写入**，程序明确报错并跳过：

```
【已跳过 1 行：机型解析失败，C 列未写入】
  第 7 行（D7）：机型列解析不出机型，已跳过（原始内容：素皮）
  → 请在该行机型列补充完整机型后重跑，不要留空。
```

程序**绝不会**用「适用于苹果iPhone」这类编造的机型占位。

**想换列**：改 `config/required_words.yaml` 的 `model_column`，或运行时加 `--model-col E`。


### 3.5 ★ 表格存放位置有要求吗？

**没有硬性要求**，放哪都能跑（命令里给完整路径即可）。但有几条建议，能避开不少坑：

| 建议                          | 原因                        |
| --------------------------- | ------------------------- |
| ✅ **放 `referexcel\` 目录**    | 和项目放一起，路径短、好管理（推荐）        |
| ✅ 路径**避免特殊符号**              | 支持，但命令行引号转义容易出错           |
| ✅ 确保**目录可写**                | 程序要在同目录生成备份文件，只读目录会失败     |
| ❌ **别放 OneDrive / 坚果云等同步盘** | 同步进程可能锁文件，导致写入失败或产生冲突副本   |
| ❌ **别放网络共享盘**               | 网络抖动会让写入中途失败（虽有重试，但没必要冒险） |
| ⚠️ **运行时别用 Excel 打开这个文件**   | Excel 会锁住文件，程序写不进去        |

**推荐做法**：直接在 `referexcel\` 里处理，处理完再把结果表拷走。

> 想输出到别处、不动原文件，加 `--out`：
>
> ```powershell

> ```

## 五、配置文件说明

**所有规则都在 `config/` 目录下的 4 个文件里，改配置不用改代码。**

### 5.1 `title_rules.yaml` —— 标题规则

```yaml
length:
  target: 100          # 目标长度
  count_mode: taobao   # 计数口径：taobao=汉字算2字符 / char=每字算1

differentiation:       # 差异化（防止标题雷同）
  enabled: true
  similarity_warn: 0.85   # 相似度超这个值告警

structure:
  patterns: [...]           # 组装模板，按行轮换
  model_keyword_quota: 15   # ★ 模型特征词最多占总长度的百分比

validate:
  check_punctuation: true   # 是否检查标点符号（用户要求名称不能有标点）
```

**想改标题长度**：改 `target`。

**想改组装顺序**：调 `patterns` 里的模板顺序，或加新模板。

**想控制模型词占比**：调 `model_keyword_quota`。

#### ★ 模型特征词配额（`model_keyword_quota`）

模型看图输出的特征词（颜色、图案、风格）**最多占总长度的这个百分比**，
剩下的长度留给运营词库。默认 `15`（即 100 字符里模型词最多占 15 字符）。

**为什么要限制**：不限制的话，模型一次给 18-24 个词会把长度吃光，
你精心整理的运营词库反而挤不进去。实测限制前后对比：

| 部分 | 限制前 | 限制后 |
|---|---|---|
| 模型特征词 | 38.7% | **7.3%** |
| 运营词库 | 2.7% | **38.0%** |

设为 `0` 表示不限制（恢复成模型词优先）。

### 5.2 `required_words.yaml` —— 必填词与词库

```yaml
must_include:          # 必须出现的词（注意：品牌词不在这里）
  - 手机壳
  - 新款
  - 防摔

brands:                # ★ 品牌表：决定机型段怎么写
  苹果:
    aliases: [苹果, iPhone, iphone]
    title_template_single: "适用于苹果iPhone{model}"  # 只有 1 个机型时
    title_template:   "适用于苹果{model}"   # 多机型：第 1 个
    title_template_2: "iPhone{model}"       # 多机型：第 2 个
    brand_words: [苹果, iPhone]
    require_brand_words: true               # 「苹果」「iPhone」必须都出现
  华为:
    aliases: [华为, huawei, HW]
    title_template_single: "适用华为{model}"
    title_template:   "适用华为{model}"
    title_template_2: "{model}"
    brand_words: [华为]
    require_brand_words: true
default_brand: 苹果    # D 列没写品牌时按哪个处理

material_group:        # 材质库
  - 液态素皮
  - 软硅胶
  ...

word_banks:            # ★ 四类运营词库（按优先级取用）
  priority: [main_words, search_words, selling_words, precise_words]
  main_words:          # 主推词：最优先
    - 透明
    - 全包
    - 超轻薄
    ...
  search_words:        # 搜索词
  selling_words:       # 卖点词
  precise_words:       # 精准词

conditional_words:     # ★ 条件必含词
  - feature: 迪士尼联名
    must_include: 迪士尼联名
    detect_in_data: [迪士尼, Disney, IP联名]   # A 列命中即带「迪士尼联名」
    detect_in_keywords: []                     # 不用图片判断，避免误判
  - feature: 磁吸
    must_include: 磁吸magsafe
    detect_in_data: [磁吸, magsafe, 磁力]
    detect_in_keywords: [磁吸, 磁力, 无线充]

padding_pool:          # 补足词池（最后的兜底）
```

**加材质**：往 `material_group` 里加一行即可。
**加运营词**：往 `word_banks` 对应类别里加。
**加特征词**：往 `conditional_words` 里加一条（如「迪士尼联名」「带挂绳」）。
**加品牌**：往 `brands` 里加一条（填 `aliases` / 三个 `title_template` / `brand_words`）。

> **为什么「苹果」「iPhone」不在必填词里**：本类目不只卖苹果壳。
> 若把苹果定为无条件必填词，华为商品会被强行塞进苹果字样（虚假品牌宣称）。
> 品牌词改由 `brands` 表按**实际品牌**自动写入，校验还会反向拦截跨品牌词。

> 注意：补足词池里**必须保留几个含英文的词**（如 `ins风`、`Q版`），
> 因为汉字算 2 字符会让总长度出现奇偶约束，纯中文词补不出奇数缺口。
> **把这类词删光会导致长度凑不满 100。**

#### ★ 名称中绝不能有空格（用户 2026-09-22 明确）

商品名称必须用**中文或英文填满**，一个空格都不能有。

长度要精确 100 字符，而汉字算 2、英文算 1 —— 总长度存在**奇偶约束**：
当缺口是奇数（尤其只差 1 个字符）时，**没有任何词能填**（最短的词也有 3 字符）。

**程序的处理方式**：不是往末尾塞空格，而是**换词翻转奇偶**：

| 手段 | 做法 |
|---|---|
| A. 奇数词前置 | 缺口是奇数时，把 `ins风`/`Q版` 这类奇数长度的词提到词池最前，让贪心一定取到 |
| B. 放弃一词重建 | 逐个放弃一个已用关键词后重建，总长度奇偶随之翻转 |
| C. 被拦词下轮再试 | 因「英文粘连」被跳过的词，留到下一个槽位再试（不再直接丢弃） |

> **手段 C 是关键**：`ins风`、`Q版` 这类**奇数长度的词几乎都以英文开头**，
> 排在机型段（结尾是数字，如 `适用于苹果18`）后面会被防粘连逻辑拦掉。
> 若直接丢弃，就永远凑不出奇数缺口，最后只能塞空格。

只有在极少数情况下仍凑不满时，才会在校验里报「无法精确凑满目标长度」，
由重试机制换一批关键词再试 —— **宁可报错，也不往名称里塞空格**。

#### ★ 四类运营词库怎么用

标题的取词顺序是：

```
模型看图特征词  →  主推词  →  搜索词  →  卖点词  →  精准词  →  补足词池
   （最贴合商品）      （你指定的优先词）               （通用兜底）
```

越靠前越优先被用上。长度不够时才会往后取，所以主推词基本都能进标题。
想调整先后顺序，改 `word_banks.priority` 即可。

#### ★ 条件必含词怎么用

有些特征**必须写进标题**，比如「是磁吸的就要带磁吸magsafe」「是支架的就要带支架」。
这类词一旦判定命中，就会作为**固定段**插入，不会被长度控制挤掉。

判定来源有两个，**任一命中**就算具备该特征：

| 来源 | 说明 |
|---|---|
| `detect_in_data` | 在商品资料（表格第一列）文本里找。如路径含「支点」→ 判定为支架 |
| `detect_in_keywords` | 在视觉模型看图输出的关键词里找。如模型说「磁吸」→ 判定为磁吸 |

> ⚠️ **想更保守**：如果你担心模型看错（比如把普通壳误判成磁吸），
> 可以把 `detect_in_keywords` 清空，改成**只从商品资料判断**：
> ```yaml
>   - feature: 磁吸
>     must_include: 磁吸magsafe
>     detect_in_data: [磁吸, magsafe, 磁力]
>     detect_in_keywords: []      # ← 清空即关闭图像判断
> ```

> 💡 程序启动时会自动检查配置冲突（同一个词既要求出现、又被列为违禁），
> 发现冲突会直接报错并列出冲突项，不会带着矛盾配置硬跑。

#### ★ 迪士尼联名怎么判定

A 列路径里出现 **`IP联名`** 或 **`迪士尼`** 字样时，标题会自动带上「迪士尼联名」。

实测路径形态：

```
Z:\1-产品图片\2-折叠\M1-云彩系列-中轴\02-IP联名\260729-缎带七宝+庄（迪士尼）+.Y\主图-梓涵
                                       ↑ 分类目录名        ↑ 具体联名款
```

两个标记**任一命中**即触发：

| 标记 | 位置 | 例 |
|---|---|---|
| `IP联名` | 分类目录名 | `02-IP联名` |
| `迪士尼` | 具体联名款名 | `（迪士尼）` |

效果（实测）：

```
有标记 → 适用华为PuraXMax粉色手机壳可爱卡通新款透明防摔超轻薄迪士尼联名磁吸magsafe支架液态素皮保护套超薄ins风
无标记 → 适用于苹果18ProMax防指纹iPhone17Pro情侣17ProMax波点手机壳18Pro高级感新款防摔Q版磁吸magsafe支架软硅胶
```

> ⚠️ **风险提示（重要）**：`IP联名` 是**分类目录名**，它本身**不等于迪士尼**。
> 目前该目录下全部是迪士尼联名，所以拿它当触发条件没问题。
> **但如果以后这个目录里放进非迪士尼的 IP（三丽鸥、宝可梦、名侦探柯南…），
> 标题会被错扣上「迪士尼联名」——虚假品牌宣称，有法律风险。**
>
> 届时请把 `IP联名` 从配置里删掉，只保留「迪士尼」：
> ```yaml
>   - feature: 迪士尼联名
>     must_include: 迪士尼联名
>     detect_in_data: [迪士尼, Disney, disney]   # ← 去掉 IP联名
>     detect_in_keywords: []
> ```

> **为什么不用图片判断**（`detect_in_keywords` 故意留空）：
> 图片里有卡通图案就判迪士尼，误判率太高。
> **宁可漏加**（少一个卖点），**不可错加**（虚假宣称）。

### 5.3 `forbidden_words.yaml` —— 违禁词库

按类别分组，出现即判定不合格并自动重写：

```yaml
absolute:        # 绝对化用语
  - 最好
  - 第一
  - 顶级
infringement:    # 品牌侵权
  - 官方授权
  - 正版
  ...
```

**加违禁词**：找到对应类别，加一行。

> 只写具体词组，不要写单个汉字（比如写「最好」而不是「最」，
>   
> 否则会误伤「最新款」）。

### 5.4 `model_config.yaml` —— 模型参数

```yaml
model:
  name: "qwen3.5:9b"        # 换模型改这里
inference:
  temperature: 0.0           # 保持 0.0（保证结果可复现）
  think: false               # 必须 false（否则慢 7.9 倍）
  num_predict: 900           # 输出上限（防止失控）
  max_retries: 3             # 网络重试次数
```

**换模型**：改 `name`，然后所有脚本自动生效。

## 七、常见问题处理

### Q1：`表达式或语句中包含意外的标记`

PowerShell 里路径带引号时必须加 `&`：

```powershell
# ❌ 错
"C:\path\to\python.exe" script.py

# ✅ 对
& "C:\path\to\python.exe" script.py
```

**最简单的办法：直接用 `.\run.bat`**，不用管这些。

### Q2：`run.bat` 报 `'n.bat' 不是内部或外部命令` 或出现乱码

这说明 `run.bat` 的**文件编码或行尾被改坏了**（比如用记事本另存、或从网页复制）。

`run.bat` 有两条硬性要求：

1. **必须是 CRLF 行尾**（不能是 LF）
2. **内容必须是纯 ASCII**（不能存成 UTF-8 中文）

**解决办法**：直接用下面这个命令重建（复制整段到 PowerShell 执行）：

```powershell
& "C:\Users\fucker\.workbuddy-ai\binaries\python\envs\default\Scripts\python.exe" -c "import io;p=r'C:\Users\fucker\Desktop\work\work0\run.bat';open(p,'wb').write(b'@echo off\r\nchcp 65001 >nul\r\nset \"PY=C:\\Users\\fucker\\.workbuddy-ai\\binaries\\python\\envs\\default\\Scripts\\python.exe\"\r\n\"%PY%\" \"%~dp0scripts\\run.py\" %*\r\npause\r\n')"
```

**或者干脆不用 bat**，直接调用 Python（注意 PowerShell 需要 `&`）：

```powershell
& "C:\Users\fucker\.workbuddy-ai\binaries\python\envs\default\Scripts\python.exe" scripts\run.py --check
& "C:\Users\fucker\.workbuddy-ai\binaries\python\envs\default\Scripts\python.exe" scripts\run.py "referexcel\work.xlsx" --dry-run
```

> 这两条命令和 `.\run.bat` 效果完全一样，只是长一点。

### Q3：`run.bat` 无法加载，因为在此系统上禁止运行脚本

那不是 bat 的问题，是 PowerShell 执行策略。用 `.\run.bat` 而不是 `run.bat`
  
（加 `.\` 前缀），或者改用 cmd。

### Q4：提示「Ollama 服务不可用」

模型服务没启动。双击运行你的 `启动模型服务.bat`（见 1.2 节）。

### Q5：提示「未在单元格中发现图片」

- 确认图片确实在第 2 列
- 确认图片是**插入到表格里**的，不是写了图片路径
- 如果图片是 `=IMAGE("网址")` 公式引用的，需要联网，请改成插入本地图片

### Q6：跑到一半报 502 / 连接中断

Ollama 服务崩了。程序会自动重试 3 次；若仍失败：

1. 重启模型服务（见 Q4）
2. 重新跑一遍命令（**已生成的行会重新生成，结果一致，不用担心**）

### Q7：Excel 打开时提示「需要修复」

立即用备份恢复：

```powershell
Copy-Item "referexcel\work_backup_日期时间.xlsx" "referexcel\work.xlsx" -Force
```

然后把备份发我排查（这说明写入模块被改动了，正常情况下不会出现）。

### Q8：生成的标题不满意

按优先级调整：

| 想改善什么      | 改哪里                                           |
| ---------- | --------------------------------------------- |
| 标题里的词不对/太少 | `required_words.yaml` → `padding_pool` 加词     |
| 材质识别不对     | 把第一列改成结构化格式（如 `液态素皮 云花系列 适配iPhone16`）         |
| 标题开头太像     | `title_rules.yaml` → `structure.patterns` 加模板 |
| 长度不对       | `title_rules.yaml` → `length.target`          |
| 某个词不该出现    | `forbidden_words.yaml` 加进去                    |

### Q9：跑得慢

单行约 3–15 秒属正常（取决于图片大小和机器负载）。
  
100 行大约 5–10 分钟。

**不要**同时开大型游戏或视频渲染，会明显变慢。
